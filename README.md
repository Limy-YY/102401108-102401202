# 校园失物招领

面向校园场景的失物招领应用（**uni-app + Vue3**），帮助师生**发布寻物 / 招领信息、集中浏览、按关键词搜索、查看详情与联系方式**，并在物品找回或归还后由发布者标记「已找到 / 已归还」，减少重复询问与无效联系。应用可直接在浏览器中运行，账号与发布内容保存在本地，同一浏览器下的用户共享一个失物招领广场。

---

## 一、快速开始（3 步跑起来）

```bash
# 1) 获取项目后进入目录
cd 102401108-102401202

# 2) 安装依赖（仅首次，约 1~2 分钟）
npm install

# 3) 启动 H5（会自动打开浏览器）
npm run dev:h5
```

启动成功后终端会显示：

```text
  ➜  Local:   http://localhost:80/
```

浏览器访问 **http://localhost:80/** 即可。**演示账号：`20240001`　密码：`campus2024`**（首次进入已自动播种，登录后首页即有内容）。

## 三、功能介绍与功能自查表（对应“功能性”）

### 功能清单

- **登录 / 注册**：学号 + 密码本地校验（学号需纯数字，注册时实时查重）；注册需学号、密码、确认密码、昵称、微信号、手机号；注册成功自动登录。
- **编辑资料**：个人中心可修改头像、昵称、微信号、手机号；联系方式与物品解耦，改一次全站同步。
- **发布信息**：支持发布「寻物」「招领」两类，填写物品名称、场所、具体位置、日期、时间、颜色、图片、细节描述；带必填校验。
- **集中浏览**：首页按「全部 / 寻物 / 招领」Tab 分类浏览广场上的全部发布，按发布时间倒序。
- **关键词搜索**：搜索页按物品名称等关键词检索，支持多关键词，并可按类型 / 时间 / 地点筛选。
- **详情与联系**：详情页展示物品完整信息，以及发布者的微信号 / 手机号（名片）。
- **标记完成**：发布者可在详情页把信息标记为「已找到 / 已归还」，标记后信息保留可浏览但沉底、角标更新，减少重复询问与无效联系；标记后还可一键「重新寻物 / 招领」恢复为进行中。

## 四、附加特点

1. **类型 / 时间 / 地点三维筛选（重点特点）**
   搜索页在关键词之外，提供「类型（寻物/招领）、时间（一天内~四周内）、地点（教学楼/图书馆/食堂等 8 类）」三个下拉筛选，可任意组合；选中项有对勾、可一键回到“全部”。
   **意义**：失主常只记得“大概在哪、什么时候丢的”，按地点和时间筛选比逐字匹配更贴近真实找物习惯。

2. **一键复制联系方式（重点特点）**
   详情页名片的微信号、手机号旁各有“复制”按钮，点击即写入系统剪贴板（H5 会提示“内容已复制”），无需手动长按选中。
   **意义**：联系发布者时少一步、不易抄错号码，移动端尤其方便。

3. **多关键词 + 智能排序**
   搜索支持空格分隔的多个关键词（要求全部命中），名称命中多的结果靠前、只在细节/地点命中的靠后，已完成的信息自动沉底，让最可能相关、仍有效的信息排在最前。

4. **完成态“保留可浏览 + 沉底 + 改角标”**
   标记完成后不删除记录，其他人仍可查看，但会明确看到“已找到 / 已归还”，从源头减少无效联系，同时保留信息可追溯。

5. **首次进入自动播种演示数据**
   空环境下自动写入演示账号和 6 条覆盖“寻物/招领 × 进行中/已完成”的物品，保证打开即有可浏览、可搜索、可点详情的内容，且不会覆盖用户后续产生的数据。

6. **联系方式与物品解耦**
   微信 / 手机号只维护在个人名片中，物品仅记录 `publisherId`；修改一次资料，所有历史发布的联系方式自动更新，避免冗余存储。

> 其中第 1、2 项为两个独立且效果明确的人性化设计。

## 六、测试如何运行

测试分三层，均可在本机一键运行，并已接入 CI：

```bash
npm test                 # 1) 单元测试（Node 内置 node:test，零额外依赖）
npm run test:component   # 2) 组件测试（Vitest + @vue/test-utils + happy-dom）
npm run test:e2e         # 3) 构建 H5 后跑 E2E（Playwright + Chromium，自动起/收静态服务器）
npm run test:all         # 一次性串行执行以上全部
```

- **单元测试**：覆盖 `validator / format / auth / storage / seed`，采用白盒的判定覆盖、条件组合覆盖、基本路径测试，并辅以边界值分析。
- **组件测试**：挂载真实组件，断言渲染与点击 / v-model / 事件回调。
- **E2E**：首次运行需安装一次浏览器：`npx playwright install chromium`。
- **规模**：单元 32 + 组件 14 + E2E 10 = **56 个用例，全部通过**。
- **CI**：`.github/workflows/ci.yml` 在每次 push / Pull Request 自动执行“安装依赖 → 单元 → 组件 → 构建 → 安装 Chromium → E2E”，失败即标红并上传 Playwright 报告，相当于每日构建门禁。

## 七、常见问题（FAQ / 故障排查）

1. **`npm install` 很慢或失败**
   可切换国内镜像：`npm config set registry https://registry.npmmirror.com`，再重新 `npm install`。

2. **端口 80 被占用 / 打不开页面**
   先确认终端里 dev server 已 ready；若 80 被占用，关闭占用程序，或重启 `npm run dev:h5`。终端会以实际输出的地址为准。

3. **想恢复初始演示数据**
   数据在浏览器 `localStorage`：在页面打开开发者工具 → Application → Local Storage → 清除站点数据，刷新后会重新播种。

4. **E2E 报“浏览器未安装”**
   执行 `npx playwright install chromium`（CI 中已自动执行 `npx playwright install --with-deps chromium`）。

5. **一键复制没反应**
   浏览器剪贴板要求安全上下文，请通过 `http://localhost` 或 `https` 访问（不要用裸 IP 非安全页面）；H5 在非安全上下文也有隐藏输入兜底。

6. **发布时时间显示异常**
   日期与具体时间已拆分为两个独立下拉框，顺序任意、互不覆盖，两者均为必填；必填项为物品名称、类型、场所、日期、具体时间。

7. **运行出现其他意外问题**
   请联系对应被测试组；建议附上终端报错与浏览器控制台信息以便定位。
